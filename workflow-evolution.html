Process

How my AI workflow evolved

The ticket workflow was rewritten 16 times in six weeks. Before each change I saved a snapshot (SKILL.md.pre-<reason>), so every rule below can be traced to the failure that caused it. Most changes came from a review comment, a QA finding, or a retro after a real run. Very few were "good ideas" added in advance.

The lessons that held up

  1. Wide reading in the main thread wastes context. If you're opening a third file to answer one question, send a scout.
  2. Ask the human what they already know, first. Domain facts the code can't show are the cheapest evidence there is.
  3. Notes go stale. Anything from memory or an earlier session is a lead to verify at the code that acts on it.
  4. Overlapping questions double the reading and echo the same unverified claim back as if it were confirmed.
  5. Collect every prerequisite in one message, including which credential variable to use, not just "the password".
  6. Masking must cover every personal field, not the one you thought of.
  7. A failing tool must say so and exit non-zero. Silent failure is how a "verified" result turns out to be empty.
  8. Don't guess the environment or the entry point. Ask, or detect it mechanically.

What I deliberately kept out

  • Blocking compaction. A PreCompact hook that refused to compact until a handoff existed made requests fail outright when compaction was recovering from a context limit. It was replaced by an early nudge from a context-size hook.
  • A web page that drives a local agent. It's convenient, but where an organisation has disabled the official remote-control feature, a polling runner would quietly recreate it. Instead, the page opens Claude Code locally with a prompt, and the human starts the work.
